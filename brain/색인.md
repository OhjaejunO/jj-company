# brain — 회사 두뇌 색인

> jj-company 레포 안의 성과·독자 지식 저장소. Obsidian 으로 이 폴더(또는 레포 루트)를 vault 로 열어 본다.
> **정본이 이미 있는 지식은 여기 두지 않는다 — 링크로 가리킨다** (§0 실물 정본. 사본이 생기는 순간 갈리기 시작한다).

## 무엇이 들어오나

지금 집이 없는 것만.

- 편별 성과 실측 (도달·좋아요·저장·킷 요청) → [[성과대장]]
- 주간 keep / test / stop 판정과 JJ 승인 → [[판정기록]]
- (예정) [[훅대장]] — 훅 유형별 반응. **데이터가 쌓이기 전에 먼저 만들지 않는다.**

들어오면 안 되는 것: 정관·SKILL·발행로그 내용의 사본, 추측값, 에이전트가 스스로 만든 «판정».

## 관련 정본 (여기 아님 — 가서 본다)

- 무엇이 나갔나 → `workshop\발행로그.md` (발행 여부 판정은 그 표로만)
- 편별 요약 → `docs\scorecard.md` — 성과 **수치의 정본은 [[성과대장]]** 이고 스코어카드는 최신값을 인용한다
- 제작 규격 → 토망치랩 SKILL.md (자회사 정본 · 본사는 수정하지 않는다)
- 회사 규칙 → `CLAUDE.md`

## 수집 절차 (주 1회 · 일요일 권장 — 주간 요약과 같은 날)

1. JJ 가 인스타 인사이트 캡처(스크린샷·화면 녹화)를 `reports\인사이트\` 에 넣는다.
   reports\ 는 gitignore — **원본 캡처는 로컬 보관, 커밋되는 것은 추출한 실측값뿐이다.**
2. 세션이 캡처를 읽어 [[성과대장]]에 행을 append 한다 — 캡처에 보이는 값만. **안 보이는 칸은 비운다 (빈 칸 ≠ 0).**
3. 세션이 성과대장을 근거로 keep / test / stop 3목록을 **제안**한다 → JJ 판정 → [[판정기록]]에 기록.
4. **승인된 keep 만** SKILL·정관 개정 후보가 된다. 개정 자체는 기존 절차(자회사 트랙·PR) 그대로다.

## 벡터 인덱스 문턱 (미룬 결정 — §0 «미룬 것은 목록에 적는다»)

- 지금은 평문 md + 이 색인 + grep. 이 규모(정관 240줄·SKILL 2,095줄·메모리 27장, 2026-09-02 실측)에서 임베딩은 없는 문제를 풀고 정본 이원화·조용한 검색 실패를 새로 만든다.
- **문턱**: 스캔로그·발행팩이 수천 건 규모가 되어 «비슷한 소재를 다룬 적 있나»를 grep 으로 못 찾게 될 때.
- 그때의 조건: ① 클라우드 아닌 **로컬 파일 기반**(sqlite-vec 류) ② 인덱스는 md 에서 언제든 재생성되는 **파생 캐시**(정본은 영원히 md) ③ 반드시 걸려야 하는 질의를 넣는 **역검증**을 같이 단다.

## 규칙

- 값은 실측만. 추측 금지 (§0). 출처(캡처 일자·JJ 구두 등)를 비고에 남긴다.
- [[성과대장]]은 append-only — 기존 행의 값 수정·삭제 금지. 오기입은 «정정» 행을 아래에 더한다.
- `.obsidian\` 은 커밋하지 않는다 (gitignore).
- 플러그인 쿼리(dataview 등)에 지식을 넣지 않는다 — 사람 눈에만 보이고 에이전트가 못 읽는 층이 생긴다. 평문 md + `[[링크]]` 까지만.
