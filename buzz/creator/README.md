# 크리에이터 팀 — Buzz 에서 새로 짓는다

> JJ 지시 (2026-09-15): 「전부 buzz에서 새로 구축해서 한다는 뜻이었어」 · 일감은 **JJ 개인
> 크리에이터 전반** · 읽는 자리도 **VPS 에서 재설계**.

## 회사 봇과 무엇이 다른가

| | 회사 봇 (`buzz/agents/`) | **크리에이터 팀 (여기)** |
|---|---|---|
| 만드는 자리 | VPS 에서 `new-agent.sh` (신원 발급·DB 멤버 삽입·reconcile) | **Buzz 앱의 「Add agent」** |
| 인격의 정본 | **레포 파일** (`BUZZ_ACP_SYSTEM_PROMPT_FILE`) | **앱의 에이전트 레코드** |
| 이 폴더의 글은 | 정본 | **붙여 넣을 초안** |
| 유닛 | `buzz-acp@<이름>` (손으로) | `buzz-remote@<앞12hex>` (**`deploy` 가 세운다**) |
| 재시작 | `on-failure` | `no` (규격 알려진 결함 6) |
| 작업 자리 | `/srv/company` (회사 레포 미러) | **`/srv/creator`** |

🔴 **앱으로 만들면 우리가 손으로 하던 두 함정이 아예 없어진다** — `reconcile-channels` 를
빠뜨려 `discovered 0 channel(s)` 로 앉는 것, `role='bot'` 으로 넣어 `@` 멘션 목록에서
숨는 것. 둘 다 앱이 알아서 한다(2026-09-10 에 각각 한 번씩 겪은 것들이다).

🔴 **그래서 이 폴더의 글은 정본이 아니다.** 앱 안의 레코드가 정본이고, 여기 있는 것은
**붙여 넣는 초안이자 우리가 읽을 사본**이다. 앱에서 고쳤으면 여기도 고쳐 두되,
**갈리면 앱이 이긴다.**

## 왜 다섯인가 (여섯이 아니라)

JJ 가 보낸 표는 여섯인데 그 사진 아래 글 자체가 「비주얼과 영상은 네 주력 포맷과 제작량에
따라 나중에 분리하고」라고 적고 있고, **우리 실측이 같은 결론**이다 — VPS 에 이미지·영상
생성 MCP 가 **0건**이라(`/root/.claude.json` 의 `mcpServers` 0건 · 붙어 있는 MCP 는
`buzz-dev-mcp` 하나) 지금 만들면 **「못 만든다」고만 답하는 봇**이 하나 는다.
같은 이유로 회사 쪽 `media` 봇도 켜지 않았다.

**여는 조건**: VPS 에 생성 경로(Higgs 계열 MCP 등)가 붙으면 그때 `visual` 을 만든다.

이 있어서 `editor`·`lead`·`writer` 로 갈랐다 — 같은 커뮤니티에서 `@` 가 겹치면
JJ 가 누구를 부르는지 헷갈린다.

🔴 **둘을 Codex 로 돌린다.** 여섯이 전부 클로드 구독을 나눠 쓰면 한도가 한 군데로 몰린다
(그 한도는 **아직 재 본 적이 없다**). 조사·수치는 코덱스로 갈라 둔다.

## JJ 가 할 일 (앱에서)

1. **에이전트 다섯 만들기** — `Add agent` 에서 칸을 채운다.
   - `Agent Name`: 위 표의 `@이름`
   - `Agent Instructions`: `agents/<이름>.md` **전문을 붙여 넣는다**
   - `Agent Harness`: 위 표의 하네스
   - `Model`: 기본값 그대로 (Claude 는 Opus)
   - `Advanced` → 명령 권한: **`Only me and you`**. 🔴 `Anyone` 으로 열면 채널의 누구든
     봇에게 명령할 수 있고, 봇은 VPS 의 작업 폴더에 접근한다.
   - **`Run on`: `jjvps`** ← 이것이 PC 를 꺼도 도는 이유다. `This computer` 로 두면
     PC 가 꺼지는 순간 다섯이 같이 죽는다.
2. **provider 설정** — `jjvps` 를 처음 고를 때 나오는 폼에서 **`작업 폴더`** 를
   **`/srv/creator`** 로 적는다(기본값 `/srv/work/remote/%i` 는 에이전트마다 빈 폴더라
   **다섯이 서로의 산출물을 못 본다**).
3. **팀 만들기** — `Create team` · 이름 `크리에이터` · `Team Instructions` 에
   `team.md` 전문 · 다섯을 전부 포함.
4. **채널 만들기** — `New channel` · 이름 `creator` · `Ongoing` · 그리고 **`Add agents`
   에서 팀을 통째로** 부른다.
5. 첫 말: `@lead 이번 주 뭐 낼지부터 정리해줘` — 다섯이 다 답하지 않고 `lead` 만 답해야
   정상이다(멘션 필터).

## 이 배선이 못 막는 것

- **구독 한도.** 다섯이 JJ 의 같은 로그인을 나눠 쓴다. **재 본 적 없다.**
- **봇이 root 로 돈다.** `deploy` 가 세우는 유닛에 `User=` 가 없다 — 회사 봇과 같은 자리이고
  같은 미결이다(`docs/clause-backlog.md` 계열).
- **작업 폴더를 공유한다.** 다섯이 같은 `/srv/creator` 에 쓴다 — 동시에 같은 파일을 고치면
  나중 것이 이긴다. `claim.ps1` 은 이 기계에서 안 돈다(C-61).
- **여기 글과 앱 레코드가 갈리는 것.** 기계가 대조하지 않는다 — 앱이 정본이다.
