# `docs/directives/` — JJ 지시서 원문 보관처

JJ 가 제작 트랙에 내리는 **지시서 원문**을 그대로 둔다. 판본마다 파일 하나이고
**받은 그대로 두며 고치지 않는다** — 여기가 «무엇을 지시받았는가» 의 정본이다.

## 왜 이 자리인가 (정관 §2 저촉 확인 · 2026-08-29)

| 후보 | §2 판정 | 결론 |
|---|---|---|
| `jj-company\docs\directives\` (**여기**) | 작업장 — **읽기/쓰기** | 🟢 저촉 없음 |
| 워크숍 편 폴더·`00_브랜드에셋` | 출장지 — **읽기 전용** (content-scout 스캔로그만 예외) | 🔴 쓰기 금지 |
| `~\.claude\skills\tomangchi\` | 라이브 스킬 = `origin/main` 의 **사본** | 🔴 사본이라 여기 쓰면 다음 배포에 지워진다 |
| `tomangchi-skill` 레포 | 자회사 정본 — §1.5 «읽되 수정하지 않는다» | ⚪ JJ 가 지시한 개정만, 별도 PR |

**지시서 원문과 스킬 개정을 나눈 이유.** 원문은 «JJ 가 무엇을 지시했는가» 라는 **본사 기록**이라
본사 레포가 맞다. 그 지시가 낳는 **제작 규격**은 자회사 정본(SKILL.md)에 들어가야 스킬이 실제로
그것을 따르는데, 그쪽은 §1.5 가 «본사 에이전트는 수정하지 않는다» 로 막아 둔 자리다 —
JJ 가 그 개정을 명시적으로 지시할 때만 `tomangchi-skill` 레포에 **별도 PR** 로 올린다.
두 자리에 같은 문장을 복사해 두지 않는다: 원문은 여기, 규격은 SKILL.md, **서로를 가리킨다.**

## 규칙

- 파일명은 `제작지시서_v<판본>_<yyyy-MM-dd>.md` 처럼 **판본과 날짜**를 담는다.
- 원문은 **손대지 않는다.** 해석·반영 계획은 별도 파일(`*_반영*.md`)에 적는다.
  - **예외는 JJ 의 개정 각주 하나뿐이다.** JJ 가 자기 지시를 고칠 때는 원 조항을 **그대로 두고**
    바로 아래에 `> **N-N 개정 (날짜 · JJ).**` 인용 블록을 붙인다. 조항을 덮어쓰지 않는 이유는
    «무엇이 어떻게 바뀌었는가» 가 지시의 일부이기 때문이다 — 고쳐 버리면 원래 뭐였는지가 사라진다.
  - 세션은 각주를 **대신 쓰지 않는다.** JJ 가 부른 문안을 옮겨 적고, 근거 실측이 필요하면
    그 실측만 세션이 만들어 각주 안에 넣는다(2026-08-29 «~죠» 오탐 4/4 가 그 꼴이다).
- **원문은 커밋한다.** 작업 트리에만 있으면 `git clean` 한 번에 사라지고 운영 서버에도 안 간다 —
  실제로 2026-08-29 에 원문이 untracked 로 하루를 났다.
- 지시서가 스킬 규격을 바꾸면, 그 반영 PR 본문이 **이 파일의 어느 절**을 근거로 삼았는지 적는다.
