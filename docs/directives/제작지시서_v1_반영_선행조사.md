## 1. 게이트 4종 — C-26 교집합 확인 (라이브 스킬 `b898b3e` 실측)

C-26 이 정확히 이 절차를 요구한다: **검사를 더할 때 기존 검사와 교집합이 비지 않는지 먼저 본다.**
각자로는 타당한 두 검사가 부딪히면 **통과할 수 있는 입력이 하나도 없어진다.**

### 🔴 ④ 캡션 크레딧 블록 — **정면 충돌. 이대로는 넣을 수 없다**

새 요구: 캡션에 **Source/Tool 크레딧 블록**.
기존 `[6]` 캡션 게이트(v3.42):

```python
ok("Source 류 출처 표기 없음 (출처 단일화 — 카드 크레딧 담당)",
   not re.search("(?im)^[ \t]*(source|출처)[ \t]*[:：]", cap), since="v3.42")
ok("출처 나열·URL 없음 (카드 크레딧 담당)",
   "🔗" not in cap and not re.search(r"(https?://|[a-z0-9.\-]+\.(com|io|ai|eu|co|org|net)/?)", ...))
```

`Source:` 나 `출처:` 로 시작하는 줄을 **금지**하고, 도메인·URL 도 **금지**한다.
즉 **요구와 금지가 동시에 참이라 통과 조합이 없다** — C-26 사례 ①②와 같은 꼴, **세 번째**다.

이 금지는 실수가 아니라 **v3.42 에서 «출처 단일화 — 카드 크레딧 담당» 이라는 사유로 일부러 넣은 것**이다.
그러므로 고르는 것은 산출물이 아니라 **정책**이다 — JJ 판정이 필요하다:

1. **v3.42 출처 단일화를 폐기**하고 캡션에도 출처를 둔다 (카드 크레딧과 이중 표기가 된다)
2. **캡션은 그대로 두고** 크레딧 블록을 고정 댓글로 옮긴다 (§5.9 각주와 자리가 겹치는지 봐야 한다)
3. `Source:` 꼴을 피하는 **다른 표기**로 블록을 정의한다 (그러면 금지 정규식에 안 걸린다 — 다만
   그것은 «검사를 피해 문안을 비트는» 것이라 §0 «검사가 틀린 것을 요구하면 검사부터 고친다» 와 어긋난다)

**판정 전까지 ④ 는 구현하지 않는다.**

### 🔴 ① «공식» 빈도 ≤2 — **단위가 정해져야 한다**

ep39 실측 (카드 6장):

```
카드 합계 8회 · 카드별 01=2 02=2 03=2 04=1 05=1 06=0
```

- **«편당 ≤2»** 로 읽으면 ep39 는 8회로 **크게 초과**한다 — 사실상 전면 재작성이다.
- **«카드당 ≤2»** 로 읽으면 ep39 는 **정확히 상한**이라 통과한다.

같은 문장이 정반대 판정을 낸다. 원문에서 단위를 확인해야 한다.
예외(«검증 경계 소재 카드»)의 **선언 방식**도 원문 확인 후 설계한다 —
지금 만들면 예외를 쓰는 쪽이 예외의 뜻을 정하게 된다.

### 🔴 ② 촌평 어미 상한 ≤3 — **[2] 어미 게이트와 겹치는 범위를 봐야 한다**

기존 `[2]` 는 카드의 **모든 문장**이 해요체로 끝날 것을 **요구**한다:

```python
HAEYO  = re.compile(r"(어요|아요|에요|예요|죠|세요|까요|네요|데요|래요|해요|워요|려요|줘요|돼요|봐요|게요|요)[.!?…»」)]*\s*$")
HAPSYO = re.compile(r"니다[.!?…»」)]*\s*$")
```

- «촌평 어미» 가 위 목록의 **좁은 부분집합**(예: `죠`·`네요`·`군요` 같은 평가조)이면 **충돌 없다** —
  나머지 문장이 다른 해요체 어미로 `[2]` 를 만족시킬 수 있다.
- 그러나 «촌평 어미» 를 **해요체 전반**으로 정의하면 **충돌한다**: `[2]` 는 전 문장에 해요체를
  요구하는데 ep39 만 해도 카드 문장이 30줄이라, «편당 3회» 와 동시에 참일 수 없다.

**어느 쪽인지는 원문의 정의에 달렸다.** 목록을 원문에서 그대로 가져와 `HAEYO` 와 교집합을 뜬 뒤
구현한다 — 내가 목록을 지어내면 그 목록이 조문이 된다.

### 🟡 ③ 카드 제목 6~12자 — 충돌은 없으나 **현물이 거의 다 걸린다**

기존 헤드라인 제약은 **길이가 아니라 줄 수·폭**이다(`[3-3]` 헤드라인 ≤2줄, 핵심줄 폭 ≤952px).
**자수 상한 상수는 없다.** 판 가독성(`MIN_GLYPH_MEDIAN = 20` · `MIN_GLYPH_PX = 10`)은
**도해 판 안의 글자**를 재는 것이라 카드 헤드라인과 대상이 다르다 — **교집합 없음.**

다만 ep39 실측은 이렇다:

```
🔴 01 17자  로그인이 필요한 사이트도 맡아요
🔴 02 18자  비밀번호는 보지 않는다고 적었어요
🔴 03 23자  로그인 창부터 인증번호까지 이렇게 흘러가요
🟢 04 11자  세 요금제부터 열려요
🔴 05 18자  결제 직전에는 멈추고 다시 물어요
🔴 06 14자  값도 화면에 그대로 나와요
   표지 18자 / 11자
```

**6장 중 5장이 초과**다. 검사 자체는 안전하지만 **적용 시점**을 정해야 한다 —
ep40 부터인지, 기존 편 소급인지. (소급이면 ep39 는 헤드라인 전면 재작성이다.)

### 각 검사의 역검증 설계 (L-009 — 구현 시 같이 넣는다)

케이스를 **서로 분리한다.** 한 입력에 둘을 넣으면 «새 검사가 없었어도 잡혔을 입력»이 되어
그 검사의 값어치가 증명되지 않는다.

- ① 상한 초과 표본이 **걸릴 것** / 상한 정확히 = 표본이 **통과할 것**(경계) / 예외 선언 표본이 **통과할 것**
- ② 촌평 어미 4회 표본이 **걸릴 것** / 3회 표본이 **통과**하되 **`[2]` 도 같이 통과할 것**(핵심)
- ③ 5자·13자가 **걸릴 것** / 6자·12자가 **통과할 것**(양쪽 경계를 따로)
- ④ (판정 후) 블록 없는 캡션이 **걸릴 것** / 있는 캡션이 **통과하되 `[6]` 도 같이 통과할 것**

②④ 의 «**기존 게이트도 같이 통과**» 가 이 설계의 핵심이다 — 새 검사만 보면 충돌을 못 본다.

## 3. ep39 «보류 보관» (⑤) — 요청한 자리가 §2 에 걸린다

요청은 «ep39 상태를 보류 보관으로 기록 · 소재큐 #19 상태 표기 동일» 이었다. 그런데 둘 다
**워크숍 안**이다:

- 편 폴더 `...\workshop\02_제작중\ep39_챗지피티로그인\`
- 소재큐 `...\workshop\03_소재큐\인수인계_대기함.md` (#19 블록)

정관 §2 는 워크숍을 **읽기 전용**으로 두고, 예외는 content-scout 의 `스캔로그\` 하나뿐이다.
그래서 **에이전트가 그 두 자리에 상태를 적을 수 없다.** 아래에 사실만 남기고,
워크숍 쪽 표기는 **사람이 하거나 §2 예외 조항을 먼저 신설**해야 한다.

### 기록 (파일 이동 없음 · 워크숍 무변경)

- **편**: ep39 «ChatGPT 가 대신 로그인해요» — `02_제작중\ep39_챗지피티로그인\`
- **상태**: **보류 보관** (2026-08-29). 제작 지시서 v1 반영 대기.
- **완성도**: 덱 9장 완성 · 편 게이트 27항 `STATUS: OK` · 유통 원고·승인 초안까지 생성.
  **발행 0건 · 전달 0건 · 승인 폴더 비어 있음.**
- **보류 사유**: 지시서 v1 이 카드 제목 자수·«공식» 빈도·캡션 크레딧 블록을 바꾼다면
  이 편의 **헤드라인 6장 중 5장과 캡션이 새 규격에 걸린다**(§1 실측). 발행 후 규격이 바뀌면
  같은 편을 두 규격으로 설명하게 된다.
- **소재큐 #19**: 현재 «🟢 승격 2026-08-27 (JJ 판정) — 활성 후보 · ep35 1순위» 로 적혀 있고
  **소진 표기는 없다.** 보류 표기를 더하려면 위 §2 제약 때문에 사람 손이 필요하다.
- **되돌리는 비용**: 0 에 가깝다 — 산출물은 그대로 있고 게이트도 통과 상태다.
  규격이 정해지면 바뀐 항목만 다시 만들면 된다.

## 5. 4-1(캡션 첫 줄 훅) ↔ 게이트 `[6]` 교집합 — **공집합 아님 · 조건부 양립** (2026-08-29)

**게이트 `[6]` 실물** — 라이브 `epcheck.py`:

캡션 첫 줄이 **표지 두 줄을 공백으로 이은 것과 글자 그대로 같아야** 한다.
4-1 은 그 첫 줄을 «질문형 또는 수치 선언형, 이모지 1개 이내» 로 요구한다.

**🟢 공집합이 아니다.** 두 요구가 거는 대상이 다르다 — `[6]` 은 **동일성**만 보고 문장의 꼴을
묻지 않는다. 4-1 은 **꼴**을 정한다. 표지 훅 자체를 질문형·수치 선언형으로 쓰면 둘이 동시에 참이다.

### 양립 조건 (구현 시 이대로 간다)

1. **4-1 의 검사 자리는 캡션이 아니라 표지(`COVER`)다.** 캡션 첫 줄을 따로 손대는 순간 `[6]` 이
   걸리므로, 4-1 은 사실상 **표지 훅 규격**이다. 캡션에 검사를 걸면 `[6]` 과 부딪힌다.
2. **`[0.5]` 와도 같이 만족해야 한다** — 표지 훅에는 소재 고유명사가 ≥1 개 있어야 한다
   (`COVER_NOUNS`). 즉 훅은 **«질문형 또는 수치 선언형» ∧ «고유명사 포함»** 이다.
   둘은 동시에 만족 가능하다(예: 「ChatGPT 가 로그인까지 해준다고요?」).
3. **이모지 1개 이내**는 표지 훅 텍스트 기준이다. 현행 표지 렌더러는 훅에 이모지를 넣지 않으므로
   기본값이 0 이고, 상한만 거는 검사가 된다.

### 실측 — 현행 ep39 표지는 4-1 을 만족하지 않는다

```
훅 1행  ChatGPT 가 대신 로그인해요
훅 2행  비밀번호는 안 보고요
```

질문형도 수치 선언형도 아니다. **ep39 재제작 시 훅을 다시 써야 한다** — 4-1 이 「ep39 재제작부터」
적용이므로 어긋남은 아니고, 재제작 범위에 «표지 훅 재작성» 이 들어간다는 뜻이다.
