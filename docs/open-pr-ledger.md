## content-ops #8 — 씬 개념 4종 (`deadline-overlap` · `free-open` · `shutter` · `backup`)

**내용**: ep15(마누스 무료 개방 ↔ 데이터 삭제 창 겹침)용 상황 씬 개념 4종을 `cards/scenes.py` 에 등재. PR 본문에 자체 역검증(키워드 가로채기 실측)이 붙어 있다.

**실측 (2026-08-27 · 로컬 시험 머지 후 확인)**
- 네 개념 **전부 현행 `scenes.py` 에 없다** — 다른 PR 이 대체하지 않았다. 여전히 additive 하고 충돌 없이 머지된다(자동 머지 성공).
- PR 이 스스로 적은 역검증이 그대로 재현된다: `겹침`→`deadline-overlap` · `무료 개방`→`free-open` · `셔터`→`shutter` · `백업`→`backup` · `마감 겹침`→`deadline`(기록된 가로채기) · 없는 개념→`None`.
- 🔴 **그런데 새 충돌이 하나 생겼다.** PR 작성(8/15) 이후 머지된 **`free-lane-more-items`(ep33, PR #19 · 8/26)** 의 첫 키워드가 **`무료 개방`** 이다. `_concept_key` 는 **부분 문자열 매칭 + 먼저 선언된 개념이 이긴다** — 시험 머지 상태에서 `무료 개방` 은 **`free-open` 으로 간다.** 즉 **#8 을 그대로 머지하면 ep33 계열 호출이 조용히 다른 씬을 받는다.**

**판정안 — 🟡 조건부 머지 (충돌 해소 후)**
1. `free-open` 의 키워드에서 **`무료 개방` 을 뺀다**(남는 것: `무료 풀림`·`개방`·`요금 면제`·`공짜`·`free-open`). 또는 `free-lane-more-items` 보다 **뒤에 선언**되도록 순서를 옮긴다. 둘 중 하나면 족하다.
2. 해소 뒤 **양쪽 호출을 다시 잰다** — `무료 개방`→`free-lane-more-items` · `무료 풀림`→`free-open` **둘 다** 확인(한쪽만 보면 반대 가로채기를 못 본다).
3. 그 상태로 머지.

**닫기(폐기)를 권하지 않는 이유**: 네 개념은 서비스와 무관한 **구조**(무료 개방 이벤트 / 창 겹침 / 점검 차단 / 이관 마감)라 재사용 가치가 남아 있고, ep15 는 이미 발행됐지만 개념 라이브러리는 편과 수명이 다르다.

**남은 위험 (적어 둔다)**: `_concept_key` 의 «먼저 선언이 이긴다» 는 **개념이 늘수록 조용한 가로채기가 늘어나는 구조**다. 지금은 PR 본문·주석이 사람에게 경고할 뿐 **기계 검사가 없다.** 개념 등재 시 «새 키워드가 기존 개념에 먼저 걸리는가»를 보는 자체 검사(양방향)를 `scenes.py` 에 두는 것이 근본이다 — 별건 제안.
