## 1. Threads — 🟢 **된다 (오늘 실측)**

**기존 `THREADS_TOKEN` 으로 인사이트가 읽힌다.** 새 자격·새 앱·새 비용이 없다.

프로브: `py scripts\threads_insights_probe.py` (A등급 · **GET 만** — 발행은 POST 라
구조적으로 못 나간다 · `--self-test` 로 역검증)

### 실측값 (2026-08-30 · @ai_tomangchi.lab)

| 층 | 지표 | 결과 |
|---|---|---|
| 사용자 | `views` | **293** |
| 사용자 | `followers_count` | **1** |
| 사용자 | `likes`·`replies`·`reposts`·`quotes` | 전부 **0** (200 · 값 있음) |
| 사용자 | `follower_demographics` | 🔴 **HTTP 400** (`Invalid parameter`) |
| 게시물 목록 | `GET /me/threads` | **2건** — 루트 포스트만 |
| 게시물 (ep39 루트) | `views` **278** · `replies` **4** · `likes`·`reposts`·`quotes`·`shares` **0** | |

### 이 실측이 말해 준 것 넷

1. **비용·자격 장벽이 없다.** 이미 있는 토큰이 그대로 읽는다.
2. 🔴 **시각은 UTC 로 온다.** ep39 루트가 `2026-08-29T16:38:08` 로 왔고 이것이
   **발행로그의 `2026-08-30 01:38 KST` 와 같은 순간**이다. 수집기를 만들면 **시간대 변환이
   첫 결함 자리**다 — 측정 필드에 오프셋을 의무화하는 이유가 여기 있다.
3. 🔴 **`/me/threads` 는 루트만 준다.** ep39 는 5포스트 체인인데 목록에는 루트 하나다.
   체인 뒷부분은 답글로 달려 있고, **편 단위 합산은 루트 + 답글을 따로 모아야** 성립한다.
   `replies=4` 가 우리 자신의 이어짓기일 가능성이 크다 — **셈법 확정 전까지 참고값**이다.
4. **`saved` 지표가 없다.** 광고주가 보는 저장 축은 Threads 로는 못 연다(§4-2).

## 2. 인스타그램 — 🟡 **요건은 낮은데, 결정적 미지수 하나가 남았다**

### 2-1. 요건 (공식 문서 2026-08-30 조회)

| 항목 | 내용 |
|---|---|
| 계정 유형 | **프로 계정(비즈니스 또는 크리에이터) 필수.** 개인 계정 미디어는 조회 자체가 안 된다 |
| 인증 경로 | **Instagram Login** — `instagram_business_basic` + `instagram_business_manage_insights` |
| 페이스북 페이지 | **선택** (Instagram Login 경로는 페이지 없이 된다) |
| 비용 | 공식 문서에 **요금 언급 없음** — 무료로 읽는다 |
| 대안 경로 | Facebook Login — `instagram_basic`·`instagram_manage_insights`·`pages_read_engagement` (+ 비즈니스 관리자 역할이 있으면 `ads_*`) |

**우리 계정은 이미 프로 계정일 가능성이 높다.** 근거 — Manychat 이 **프로 계정에만 붙고**,
발행로그 규칙 5 가 「Manychat 에 실제로 세팅된 값을 적는다」로 트리거 운용을 전제한다.
🔴 **다만 이것은 추론이다.** 확인은 인스타 앱 설정 한 화면이고, **JJ 육안 1회**로 끝난다.

### 2-2. 🔴 결정적 미지수 — 캐러셀에 인사이트가 붙는가

공식 문서에 **「앨범 *안의* 미디어에는 인사이트가 없다」**로 적혀 있다. 이 문장이
**«캐러셀 컨테이너 자체»까지 뜻하는지 «자식 장들만» 뜻하는지 문서로는 안 갈린다.**

🔴 **우리 인스타 산출물은 전부 캐러셀(9장 덱)이다.** 그래서 이 한 줄이 인스타 경로 전체의
값어치를 정한다 — 컨테이너에 붙으면 `saved`·`shares`·`reach` 가 다 열리고, 안 붙으면
**인스타에서 얻을 수 있는 것이 계정 층뿐**이다.

**갈리는 법**: 토큰이 서면 `GET /{캐러셀_미디어_id}/insights?metric=saved,shares,reach`
**한 번**. 문서를 더 읽어서 갈리는 문제가 아니다 — §0 「실물을 조회할 수 있는 것은 실물이 정본」.

### 2-3. 두 갈래

| | **ⓐ Graph API 수집** | **ⓑ JJ 주간 수동 스냅샷** |
|---|---|---|
| 비용 | 0원. 대신 **앱 등록·토큰 발급 회차 1개** | 0원. 대신 **매주 JJ 5~10분** |
| 선행 조건 | 프로 계정 확인 · Meta 앱 · 권한 2종 · 장기 토큰 갱신 절차 | 없음 — 오늘 시작 가능 |
| 리스크 | 토큰 만료·권한 변경으로 **조용히 멈추는** 것(§4 auth_check 계열로 감시). 앱 심사는 **자기 계정이면 불필요** | 사람이 걸러 적으므로 **누락·기억 보정**이 섞인다. 빠뜨린 주는 영영 못 채운다 |
| 되돌림 | 완전 — 토큰 폐기·앱 삭제 | 완전 |
| 얻는 것 | 편별 `saved`·`shares`·`reach` (캐러셀 미지수 해소 시) · 자동 적재 | 계정 팔로워·인사이트 화면 육안값 |
| 못 얻는 것 | 캐러셀에 안 붙으면 편별 전부 | 편별 정밀값 · 자동화 |

**섞는 안(권장 후보)**: **ⓑ 로 이번 주부터 기준선을 뜨고, ⓐ 는 캐러셀 실측 한 번으로
값어치를 확인한 뒤** 회차를 연다. 설계도 §2-1 「선설치·소급 불가」가 «완벽한 경로를
기다리다 기준선을 못 만드는 것」을 가장 크게 친다 — **ⓑ 는 오늘 시작할 수 있다.**

## 3. 댓글 트리거 DM (ManyChat 류) — C-27 6-1 판정 자료

### 3-1. 먼저: 우리는 이미 이 도구를 쓰고 있다

**새 도입이 아니라 «활용 확대» 판정이다.** ManyChat 계정은 이미 있고 트리거 키워드를
콘솔에서 사람이 세팅해 왔다(발행로그 규칙 5). **2026-08-18 에 확정한 것은 «공개 API 연동
보류»이지 «도구 사용 금지»가 아니다** — `docs\infra-manychat-api.md` 를 그대로 유지한다.

### 3-2. 비용 (🔴 전부 2차 출처 — 정본은 콘솔이다)

✅ **실값으로 갈렸다 (2026-08-30 · JJ 콘솔).**

| 항목 | 실값 |
|---|---|
| 요금제 | **Manychat Essential** |
| 가격 | **$17/월** |
| 활성 연락처 | **250** |
| 다음 청구 | **2026-09-29** |

🔴 **아래 표는 틀렸다 — 기록으로만 남긴다.** 이 세션이 3자 블로그에서 뜬 값이고,
**우리 요금제가 그 표의 어느 칸도 아니었다.**

| ~~요금제~~ | ~~값 (2차 출처)~~ |
|---|---|
| ~~Free~~ | ~~$0 · 월 활성 연락처 25명~~ |
| ~~Pro~~ | ~~$39/월 (연납 $29) · 2,500 연락처~~ |

**왜 틀렸는가가 이 칸의 값어치다.** 공식 도움말·요금 페이지가 **HTTP 403** 으로 막혀
세션이 못 읽었고, 그 자리를 3자 블로그가 채웠다(x.ai 약관 때와 같은 꼴). 정관 §0
«실물을 조회할 수 있는 것은 실물이 정본이고 문서는 조회 결과다» — **조회처가 콘솔이었고,
세션은 거기 못 들어간다.** 레퍼런스 ④ 위조 편이 「2차 출처의 제품 사양」을 지목한 그 자리다.

**남은 확인 하나**: 세팅된 트리거 키워드 목록(콘솔 육안). 「킷 요청 수」를 세려면 필요하다.

### 3-3. 리스크 — 자동 DM 의 플랫폼 규정

| 위험 | 실질 |
|---|---|
| 계정 제재 | ManyChat 은 **Meta 공식 파트너 경로**를 쓰는 도구다 — 비인가 자동화(브라우저 조작)와 성격이 다르다. 🔴 **파트너 지위·정책 세부는 이번 세션에서 공식 문서 접근이 막혀 확인 불가** |
| 메시지 창 | 인스타 메시징은 **사용자 상호작용 뒤 일정 시간 안**에만 자유 발신이 된다. 댓글 트리거는 **사용자가 먼저 행동한 것**이라 이 창 안에 든다 — 우리 용법이 규정의 험한 쪽이 아니다 |
| 내용 리스크 | 자동 DM 이 **링크 하나 + 한 문장**이면 스팸 판정과 멀다. 연속 발송·팔로우 유도 반복이 위험한 쪽 |
| 되돌림 | **높다** — 콘솔에서 플로우 끄면 즉시 멈춘다. 이미 나간 DM 은 안 돌아온다 |

### 3-4. 🔴 정관 §6 정합 — 이것이 판정의 핵심이다

§6 은 **「외부 발송 (이메일, DM, SNS 게시, 댓글)」을 금지**하고, 예외는 Threads 텍스트
하나뿐이다. **자동 DM 은 문자 그대로 이 금지의 한복판이다.**

**그런데 가르는 기준은 §0 대로 «되돌림 비용»이지 «DM 인가»가 아니다.** 갈래 셋을 나눠 둔다:

| 갈래 | 무엇 | §6 과의 관계 |
|---|---|---|
| ⓐ **사람이 콘솔에서 플로우를 켠다 · 발송은 ManyChat 이 한다** | 지금 하고 있는 것 | **§6 대상이 아니다.** 발송 주체가 에이전트가 아니다 — §6 이 막는 것은 **에이전트의 발송**이다 |
| ⓑ 에이전트가 ManyChat API 로 DM 을 쏜다 | `sendContent`·`sendFlow` | 🔴 **정면 금지.** `infra-manychat-api.md` 도 「C등급 · 사람이 누르는 버튼의 뒷단으로만」이라 적었다 |
| ⓒ 에이전트가 트리거·플로우를 **만들거나 고친다** | — | **불가능하다** — 그 API 가 존재하지 않는다(2026-08-18 조사). 구조가 이미 닫았다 |

**따라서 판정해야 할 것은 «DM 을 허용할까»가 아니라 «ⓐ 를 성장 장치로 정식화할까»다.**
ⓐ 는 이미 §6 밖이고, 정식화가 더하는 것은 **③ 캡션 규격(트리거 문구)** 과 **④ 스코어카드
「킷 요청 수」 칸**뿐이다.

### 3-5. 판정에 필요한 것 (JJ)

1. ~~**콘솔 실값 3종**~~ ✅ **2026-08-30 JJ 확보** — Essential · $17/월 · 250 · 청구 9/29. 남은 것은 트리거 키워드 목록 하나.
2. **트리거 문구를 캡션 규격에 넣을지** — 넣으면 지시서 4장 각주 + 게이트 짝이 따라온다.
3. **킷 요청 수를 어떻게 셀지** — ManyChat 통계 API 가 없으므로(2026-08-18 확정)
   **콘솔 육안 또는 봇 필드 카운터**다. 🔴 **세는 장치 없이 켜면 §2 계기 원칙 위반**이다 —
   「무엇이 곡선을 움직였는지 못 가르는」 상태가 된다.
