### 최종 판정 (2026-08-18 · JJ 확인)

> **등급 이탈이 아니다 — 대화형 세션 산출물의 «인수인계 누락»이다.**
> 만든 쪽이 PR 을 열어 두고 그 사실을 넘기지 않아 이틀 동안 아무도 몰랐다.
> **단, 포렌식 과정에서 «분리 부재»(구조 구멍)가 드러났고 본 보수로 해소했다.**

🔴 **실장 오판정 경위 — 귀속 검증 없이 사건으로 승격했다.**
「A등급 부서가 PR 을 만들었다」는 귀속이 **커밋 author·트레일러·실행 로그를 보기 전에**
먼저 결론으로 섰고, 그 상태로 «등급 이탈 1건 · 8/15 발생»이라는 사건 기록과 차단 조치가
지시됐다. 실제로는 **author 가 사람 계정이고 날짜도 8/16** 이었다.

**재발 방지 — 귀속 주장은 커밋 포렌식 후에만 한다.** 「누가 했나」를 적기 전에 최소한
아래 넷을 본다. 하나라도 못 보면 **«주체 미확인»으로 적고 부서 이름을 쓰지 않는다.**

| 볼 것 | 명령 |
|---|---|
| PR author | `gh pr view <N> --json author` |
| 커밋 author / committer | `git log -1 --format="%an <%ae> / %cn <%ce>"` |
| 트레일러 (`Co-Authored-By`) | `git log -1 --format="%B"` |
| 그 시각에 그 부서가 돌았는가 | `logs/scheduled/` 실행 로그 |

**부서에 사고를 잘못 귀속시키는 비용이 크다** — 그 기록이 다음 판단의 근거가 되고,
그때는 아무도 다시 확인하지 않는다. 이번에도 그 기록 위에 차단 조치가 얹힐 뻔했다.

→ **판정: 등급 이탈 0건 / 인수인계 누락 1건 / 구조 구멍 1건 — 구멍은 §4 로 해소.**

## 3. 역검증 — 어디까지 실제로 막히나

**차단이 작동하는지 말로 적지 않고 실제로 눌러 봤다.**

| 시도 | 결과 |
|---|---|
| `git push --force-with-lease` | 🟢 **거부됨 (2회).** `Bash(git push --force*)` deny 규칙이 실제로 발동한다 |
| `git push` (일반) | ⚪ 통과 — 의도된 동작 |
| `gh pr create` | 🔴 **거부되지 않는다.** allow 목록에 `Bash(gh pr *)` 가 있다 |

- **deny 규칙 자체는 헛돌지 않는다** — force push 가 두 번 다 실제로 막혔고, 그래서
  이번 #48 은 리베이스+force 대신 **머지 커밋**으로 우회 없이 해소했다.
- 🔴 **그러나 PR 생성은 열려 있다.** 그리고 **그 구멍은 deny 규칙으로 못 막는다** —
  세션 전역이라 사람과 B등급 부서까지 같이 막힌다. **막을 자리가 설정에 없다.**

## 4. 조치 — 도구 부재로 바꿨다 (2026-08-18 구조 보수 · JJ 승인)

**`ops-auditor` 의 `tools` 에서 `Bash` 를 뺐다.** `Read, Glob, Grep, Write` 만 남는다.
`git`·`gh` 를 부를 수단 자체가 없으므로 **경계가 조항이 아니라 도구 부재로 지켜진다.**

| 바뀐 것 | 내용 |
|---|---|
| `scripts/morning-vault-health.ps1` | 에이전트 호출 **전에** `vault_audit.py` 와 `gh pr list` 를 돌려 `logs/audit-data/` 에 결과 파일 2개를 남긴다 |
| `.claude/agents/ops-auditor.md` | `tools` 축소 · 「감사 데이터는 읽는다」 절 · 점검 항목 6 「열린 PR」 신설 |
| `scripts/prompts/morning-vault-health.md` | 데이터 파일 경로 2개를 프롬프트로 주입 |

**`Write` 는 남겼다 — 리포트를 써야 하기 때문이다.**
🔴 **이것이 이번 보수에서 가장 중요한 발견이다**: 기존 에이전트는 `Bash` 로 리포트를
쓰고 있었다. **`Bash` 만 빼면 리포트를 못 쓴다** — 「막았는데 일도 안 되는」 상태가
「성공」으로 보였을 자리다. 쓰기 범위는 `reports/`·`logs/` 이고 vault 쓰기는
`settings.json` 의 `Edit(vault)` deny 가 막는다(그 규칙은 Write 에도 적용된다).

**조용한 실패 방지 장치도 같이 넣었다.**
- `vault_audit.py` 가 0 으로 끝나도 **`BROKEN_LINKS_COUNT=` 줄이 없으면 FAIL** 시킨다.
  빈 파일을 읽고 «문제 없음»을 보고하는 것이 가장 위험한 통과다.
- `gh pr list` 실패는 치명적이지 않게 두되 **`UNAVAILABLE` 로 기록**한다 —
  에이전트가 «열린 PR 0건»이 아니라 «확인 불가»로 적게 하기 위해서다.

### 이전 조치 (문서) — 유지한다

`ops-auditor.md` 의 **저장소 쓰기 금지** 조항은 그대로 둔다. 도구가 막아도 **왜 막았는지**가
문서에 있어야 다음 사람이 `Bash` 를 되돌려 놓지 않는다.

## 5. 바뀐 흐름

    이전:  스케줄 → 에이전트 → (Bash) vault_audit.py → 리포트
    현재:  스케줄 → vault_audit.py + gh pr list → logs/audit-data/ → 에이전트(Read) → 리포트(Write)

**판정·리포트 작성은 그대로 에이전트가 한다 — 잃는 기능이 없다.**

| 1 | 데이터 수집이 실제로 값을 내는가 | `py scripts/vault_audit.py` | 🟢 **확인** — exit 0, `BROKEN_LINKS_COUNT=685` 등 산출 |
