## 3. 역검증 — 어디까지 실제로 막히나

**차단이 작동하는지 말로 적지 않고 실제로 눌러 봤다.**

| 시도 | 결과 |
|---|---|
| `git push --force-with-lease` | 🟢 **거부됨 (2회).** `Bash(git push --force*)` deny 규칙이 실제로 발동한다 |
| `git push` (일반) | ⚪ 통과 — 의도된 동작 |
| `gh pr create` | 🔴 **거부되지 않는다.** allow 목록에 `Bash(gh pr *)` 가 있다 |

- **deny 규칙 자체는 헛돌지 않는다** — force push 가 두 번 다 실제로 막혔고, 그래서
  이번 #48 은 리베이스+force 대신 **머지 커밋**으로 우회 없이 해소했다.
- 🔴 **그러나 PR 생성은 열려 있다.** 그리고 **그 구멍은 deny 규칙으로 못 막는다** —
  세션 전역이라 사람과 B등급 부서까지 같이 막힌다. **막을 자리가 설정에 없다.**

## 5. 진짜 차단으로 가는 길 (착수 전 · 제안)

**ops-auditor 에서 `Bash` 를 떼는 것이 유일한 구조적 차단이다.** 도구가 없으면
허용목록과 무관하게 `git`·`gh` 를 부를 수 없다.

가능한 이유: **에이전트가 `Bash` 를 쓰는 곳은 `scripts/vault_audit.py` 실행 한 곳뿐**이고,
그 실행은 이미 스케줄 래퍼(`scripts/morning-vault-health.ps1`)가 감쌀 수 있다.

    현재:  스케줄 → 에이전트 → (Bash) vault_audit.py → 리포트
    제안:  스케줄 → vault_audit.py → 결과 JSON → 에이전트(Read 전용) → 리포트

- 에이전트 `tools` 를 `Read, Glob, Grep` 로 줄인다.
- 판정·리포트 작성은 그대로 에이전트가 한다 — **잃는 기능이 없다.**
- ⚠️ **착수 전 역검증 필수**: ① 스크립트가 실제로 결과 파일을 남기는지 ② 에이전트가
  `Bash` 없이 리포트를 완성하는지 **양쪽**을 본다. 한쪽만 보면 «막혔지만 일도 안 되는»
  상태가 «성공»으로 보인다.
