# 계획 — 브랜드 스크립트 정본 단일화

> **상태: 승인됨 · 착수 대기.** ep15(마누스)·힉스필드 레이어 발행이 끝난 뒤 진행한다.
> 지금 하지 않는 이유는 아래 «왜 지금이 아닌가»에 있다.

## 문제

토망치랩 브랜드 스크립트가 **두 곳에 있다.**

| | 경로 | 성격 |
|---|---|---|
| 실행 정본 | `tomangchi-lab.github.io/workshop/00_브랜드에셋` | gitignore. **모든 제작이 여기를 import 한다** |
| 버전관리 사본 | `tomangchi-skill/skills/tomangchi` | git. 스킬이 배포하는 것 |

원인은 네 겹이다.

1. **작업하는 곳과 버전관리하는 곳이 다르다.** 고치면 정본만 바뀌고, 사본은 누군가
   기억해서 복사해야만 바뀐다. 기억에 의존하는 동기화는 반드시 샌다.
2. **정본에 변경 이력이 없다.** gitignore 라 무엇이 언제 바뀌었는지 git 이 모른다.
   «사본이 뒤처졌다»를 기계가 판단할 근거가 없다.
3. **드리프트가 조용하다.** 사본이 낡아도 아무도 안 죽는다 — 제작은 정본으로 도니까.
   정관 §0 «조용히 실패하는 코드»와 같은 계열이다.
4. **사본은 아무도 실행하지 않는다.** 그래서 `brand.py` 가 통째로 없었는데도 몇 주간
   아무 신호가 없었다(2026-08-15 발견). 실행되지 않는 코드는 검증되지 않는다.

## 목표 구조

정본을 **하나로** 만든다. 사본을 없앤다.

    tomangchi-skill/skills/tomangchi/     ← 유일 정본 (git)
    workshop/ 빌드 스크립트               → sys.path 로 위 경로를 참조

`content-ops/cards` 를 참조하는 방식과 **같은 패턴**이다. 이미 그렇게 돌고 있는 선례가
있으므로 새 개념을 들이는 것이 아니다.

### 심볼릭 링크는 쓰지 않는다

`~\.claude\skills\tomangchi` 가 링크였다가 2026-08-15 사본으로 바뀐 이유와 같다 —
링크면 **체크아웃된 브랜치가 곧 라이브 정본**이 되어, 한 세션이 feature 브랜치에 두고
나오면 다른 세션·스케줄이 미승인 규칙으로 조용히 돈다. 오늘 그 함정을 뺐는데 다른
자리에 다시 놓을 이유가 없다.

## 왜 지금이 아닌가

**세 세션이 동시에 그 폴더를 쓰고 있다.** 경로를 옮기면 진행 중인 편의 빌드가 그 순간
깨진다. ep15 는 8/22 마감이 걸려 있다. 옮기는 작업 자체보다 **이전 시점 조율**이 위험한
부분이라, 발행이 끝나 아무도 그 폴더를 안 쓰는 창을 기다린다.

## 순서

1. **창 확인** — ep15·힉스필드 발행 완료, `02_제작중` 에 진행 중인 편이 없는지 확인.
   진행 중인 세션이 있으면 착수하지 않는다.
2. **파일 이전** — `00_브랜드에셋/*` 을 `tomangchi-skill/skills/tomangchi/` 로 옮긴다.
   worktree 에서 작업하고 PR 로 올린다(정관 §3).
   - 런타임에 열리지 않는 원본·참고 자산(약 9MB: `토망치 커버1~3` · `프로필` ·
     `avatar_1024` · `post_sample_8` · `endcard_v2` · `_endcard_prev`)은 **옮기지 않는다.**
     제작 소재이지 코드 의존이 아니다. workshop 에 남긴다.
3. **참조 전환** — 편 빌드 스크립트의 `sys.path.insert` 대상을 새 경로로 바꾼다.
   대상은 `02_제작중/*/build_*.py` · `verify.py` · `shoot_*.py` 와 `01_발행완료` 의
   재조립 스크립트. **기발행 산출물은 재생성하지 않는다** — 스크립트만 고친다.
4. **검증** — 새 경로에서 `_selftest.py` 통과 + 최근 편 하나를 실제로 재빌드해
   산출물 해시가 같은지 확인. 다르면 되돌린다.
5. **정리** — `00_브랜드에셋` 의 옮긴 파일 삭제. 드리프트 감사(`skill_drift_audit.py`)는
   비교 대상이 사라지므로 **함께 폐기**한다. 감사가 필요 없어지는 것이 이 작업의 목적이다.
6. **정관 반영** — §2 작업 디렉토리 표에서 브랜드 스크립트 위치를 갱신.

## 되돌리기

3번까지는 파일 복사뿐이라 되돌리기 쉽다. 5번(원본 삭제)이 되돌리기 어려운 지점이므로
**4번 검증을 통과하기 전에는 5번을 하지 않는다.** 4번에서 산출물이 달라지면 3번을
되돌리고 원인을 먼저 찾는다.

## 그때까지

드리프트 감사가 매일 아침 두 폴더를 비교한다(`scripts/skill-drift-audit.ps1`, A등급).
막을 수는 없어도 **소리는 나게** 해 둔 상태다.
