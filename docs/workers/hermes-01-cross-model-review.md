# 헤르메스 ① 크로스 모델 검수 — 양식 4 · 층: 감시 · 상태: 설계 (2026-08-26)

**JOB** 게이트(`verify.py`) 통과본을 **다른 모델**이 규격으로 재검수해 «놓친 것 목록» 을 낸다. 게이트 뒤의 2차 눈 — **게이트 대체 불가**(게이트 FAIL 은 이 자리에 오지 않는다).

**TRIGGER** 편 게이트 `STATUS: OK` 직후 사람 호출(SKILL §7 제작 순서 10번과 11번 사이). 스케줄 아님.

**INPUTS** 덱 실물(PNG/MP4) · `caption.txt`·`pinned_comment.txt`·`발행팩.md`(사본으로 전달) · SKILL 해당 절 발췌(§4.1·§5·§5.8-1·§6.1 — 절 참조가 아니라 **발췌 전달**: 이 워커는 레포를 읽지 않는다).
- 🔴 **메모리 off 가 성립 조건.** 검수는 기억이 아니라 규격으로 해야 «같은 실수를 같은 이유로» 잡는다. 전 편 기억이 있으면 «지난번엔 통과했다» 가 판정에 섞인다. 설치 실측 ③에서 off 가 실제로 값을 안 남기는지 확인되지 않으면 이 자리는 착수하지 않는다.

**PROCESS**
1. 산출물과 규격 발췌를 받는다(레포 접근 없음).
2. 카드별로 «규격 위반 의심 · 근거 절 · 실물 위치(카드 번호·줄)» 를 낸다. 의심이지 판정이 아니다.
3. 캡션·고정 댓글·킷 본문에 v3.47 ③(안 한 일 열거)·v3.52 셀프 언급·예고 잔존을 본다(게이트 `[5-4]`·`[7]` 가 어휘로 못 잡는 의미 판정 — 여기가 제 자리다).
4. `reports/<날짜>_xreview_epNN.md` 에 목록 + 마지막 줄 `STATUS:`.

**OUTPUT** 리포트 1건. 정본 쓰기 없음.

**RULES — 금지 자리** 게이트 판정을 뒤집지 않는다(«게이트가 틀렸다» 는 learnings 후보로만) · 조문 제안 금지 · 발행 금지 · 산출물 수정 금지(제안만). 지적 상한 **10건** — 넘기면 «중요 순 10 + 나머지 건수» 로 자른다(읽는 비용).

**GATE** 리포트 형식(정관 §5) + 지적마다 근거 절 번호가 있는가(없는 지적은 «근거 없음» 으로 걸러 세지 않는다). 역검증: 규격 발췌에 없는 절 번호를 단 지적 1건을 심어 걸리는지.

**성공지표** keep rate = JJ 가 채택해 수정한 지적 ÷ 낸 지적 ≥ **50%** (사흘 시범, 편 2건 이상). 부수 지표: 채택 지적 중 «게이트가 못 잡는 종류»(의미 판정) 비율.

**FAIL CONDITION** 규격 발췌를 못 받았거나 리포트를 못 쓴 경우. 지적 0건은 FAIL 이 아니다(«0건» 을 적는다).

**6질문 답** ① 산출물 사본 + 규격 발췌(사본) ② 리포트 파일은 유일 작성자, 편 폴더는 안 건드림 ③ SKILL §4.1·§5·§5.8-1·§6.1·v3.47·v3.52 발췌 ④ **메모리 · 타 편 · 검증로그(정답지를 보면 검수가 아니다)** ⑤ 지적 유형이 반복되면 → R6(게이트에 어휘 검사 추가) 또는 R7 ⑥ 같은 유형 3회 채택 → epcheck 항목 신설 제안(learnings 경유).

**하네스 판정** 봇 메모리 = **부채(off 필수)**. **채점** 반복 2 · 시간 1 · 검증 1(사람이 채택 판정) · 실패 비용 2 · 오염 2 = **8/10**.
