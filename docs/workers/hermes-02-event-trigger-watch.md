# 헤르메스 ② 사건형 트리거 감시 — 양식 4 · 층: 감시 · 상태: 설계 (2026-08-26)

**JOB** 소재큐 대기함의 **사건형 조건**(«X 가 공개되면 낸다» · «키 나오면») 을 감시처에서 실제로 폴링해, 조건이 성립한 순간 알린다. 대기함 규칙 4(«감시표 미등재 → 아무도 안 본다») 의 **잔여 절반** — 날짜형은 `handoff_schema --today` 가 해소했고(#70), 사건형은 사람이 기억해야 했다.

**TRIGGER** 매일 1회 스케줄(정관 §4 규약: 래퍼·lock·stagger·`git-sync`·STATUS). 시각은 tomangchi-scout(08:00) 앞 07:40 안 — **조건 성립 알림이 그날 스캔에 들어가게**.

**INPUTS** 대기함 레코드에서 **래퍼가 추출한 «조건 문자열 + 감시처 URL» 목록만**(공개 예정 텍스트 — 소재명·훅각도·밝힐처리 등 내부 필드는 투입하지 않는다, 공통 원칙). 감시처가 없는 레코드는 «감시처 없음» 으로 보고 — 지어내지 않는다. 대기함 원본은 봇이 읽지 않는다.

**PROCESS**
1. 대기함에서 조건형 레코드를 뽑는다(스키마 필드 `신선도마감=상시` + 메모 `조건:`·`감시처:`).
2. 감시처를 연다(WebFetch — HTML 전문이 아니라 **조건 문자열 존재 여부**만).
3. 성립/미성립/확인 불가 3값으로 적는다. «확인 불가» 는 미성립이 아니다. **성립은 «신규 / 기 발생» 을 가른다 (2026-08-26 E1 설계 수정)** — 감시 목록 등재 시점에 조건이 이미 성립이면 첫 회차에 **«성립(기 발생)» 알림을 내고** 베이스라인에 편입한다. **침묵 편입 금지.** 근거: 8/26 1회차에서 E1 «Seedance 2.5» 가 changelog 에 3건 적중했는데 «베이스라인 생성» 이라는 이유로 미성립으로 삼켜졌다(폐기 문서상 8/8경 이미 출시). 구현: `event_watch.py` 가 판정 후보(신규/기 발생/기 알림/없음)를 붙이고, `event_watch_report.py` 가 «판정 후보가 있는데 알림이 없는» 침묵 편입을 리포트에 적는다.
4. `reports/<날짜>_event-watch.md` — 성립 건은 🔴 로 맨 위, 마지막 줄 `STATUS:`.

**OUTPUT** 리포트 1건. **대기함 직접 쓰기 금지** — 성립 건을 대기함 상태로 옮기는 것은 content-scout(스키마 경유) 또는 사람.

**RULES — 금지 자리** 게이트 판정 없음 · 조문 제안 금지 · 발행 금지 · 정본(대기함·스캔로그) 직접 쓰기 금지 · **감시처를 지어 넣지 않는다**(레코드에 없으면 «감시처 없음»).

**GATE** 리포트에 레코드 수 = 대기함 조건형 레코드 수(전수 대조 — 하나라도 빠지면 FAIL). 역검증: 대기함 사본에 조건형 1건을 추가해 리포트 건수가 +1 되는지.

**성공지표** 사건 성립을 **사람보다 먼저** 알린 건수 ≥ 1 (사흘 시범엔 «감시처 폴링 성공률 ≥ 90%» 로 대체 — 사건이 사흘 안에 안 날 수 있다). keep rate 는 «알림 → 착수» 비율.

**FAIL CONDITION** 조건 목록을 못 받음 · **감지 데이터(json)를 못 씀** · 리포트 못 씀. 감시처 «확인 불가» 는 부분 표기(정관 §4).
