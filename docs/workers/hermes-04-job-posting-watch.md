# 헤르메스 ④ 채용 공고 감시 — 양식 4 · 층: 감시 · 상태: 설계 (2026-08-26)

**JOB** JJ 가 지정한 **회사·키워드 목록**의 공고 변화(신규·마감·내용 변경)만 감시해 diff 를 보고한다.

**역할 구분 — 셋이 다르다.**
| | job-scout (현행) | ④ 감시 | `ue5-job-finder` |
|---|---|---|---|
| 무엇 | 매일 웹에서 **발굴·적합도 평가**(B등급 제안) | 지정 목록의 **변화 감지**(A등급 read-only) | **수동 검색 도구** — 사람이 부를 때만 |
| 대상 | 열린 웹 | 고정 목록(회사 채용 페이지·키워드) | 사람이 준 쿼리 |
| 산출 | 후보 + 평가 + JJ 할 일 | diff 목록(평가 없음) | 검색 결과 |
④ 는 job-scout 를 대체하지 않는다 — job-scout 가 «오늘 뭐가 있나» 를 보고, ④ 는 «지난번과 뭐가 달라졌나» 를 본다. `ue5-job-finder` 는 자동화하지 않는다(수동 검색과의 역할 구분을 정의에 명시).

**TRIGGER** 매일 1회 스케줄(job-scout 08:30 뒤 — 08:45 안, stagger 규약).

**INPUTS** `departments/sales/watchlist.md`(신설 — 회사·URL·키워드, JJ 가 관리) · 전날 스냅숏 `logs/jobwatch/<날짜>.json`.

**PROCESS** 1. 목록의 URL 을 열어 공고 제목·마감·본문 해시를 수집 2. 전날 스냅숏과 diff 3. `reports/<날짜>_jobwatch.md` — 신규/마감/변경 3절 + `STATUS:`.

**OUTPUT** 스냅숏 JSON + 리포트. `applied.md`(지원 기록, gitignore) 쓰기 금지.

**RULES — 금지 자리** 적합도 평가 금지(job-scout 몫) · 지원(외부 발송) 금지 · watchlist 직접 수정 금지(JJ) · 정본 직접 쓰기 금지.

**GATE** 리포트 건수 = diff 건수(전수) · 각 건에 URL 존재. 역검증: 전날 스냅숏의 공고 1건을 지워 «신규» 로 잡히는지 / 1건 해시를 바꿔 «변경» 으로 잡히는지 — 양쪽.

**성공지표** 신규 공고를 **job-scout 보다 먼저** 잡은 비율(같은 날 중복이면 무승부) · keep rate = JJ 가 열어 본 diff ÷ 보고 diff ≥ 50%.

**FAIL CONDITION** watchlist 못 읽음 · 스냅숏 못 씀. 특정 URL «확인 불가» 는 부분 표기.

**6질문 답** ① watchlist(정본, JJ) + 채용 페이지(외부) + 전날 스냅숏(자기 산출) ② 스냅숏·리포트 유일 작성자 ③ 정관 §4·§5 · job-scout 정의(역할 경계) ④ 메모리 · `applied.md` ⑤ 오탐(변경 아님) 반복 → R6(해시 범위 조정) ⑥ 목록 편입 기준 3회 반복 → watchlist 규칙 신설(JJ).

**하네스 판정** 봇 메모리 = **부채**(스냅숏 파일이 기억이다). **채점** 반복 2 · 시간 1 · 검증 2 · 실패 비용 2 · 오염 2 = **9/10**.
