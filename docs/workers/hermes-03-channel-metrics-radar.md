# 헤르메스 ③ 채널 지표 레이더 — 양식 4 · 층: 감시 · 상태: 보류(Threads 가동 후) (2026-08-26)

**JOB** 발행 게시물의 지표(조회·저장·공유·댓글)를 채널별로 **수집만** 하고, 이상치(전 편 평균 대비 ±2σ)만 보고한다. 해석(왜 올랐나)은 하지 않는다 — 해석층 보류 사유와 같다(learnings L-005 감지/해석 분리).

**TRIGGER** 매일 1회 스케줄(정관 §4). Threads 계정 가동 + 게시물 10건 이상 뒤에 착수.

**INPUTS** 발행로그(정본, 읽기 — 게시물 목록·채널 열) · 채널 API 또는 화면(수집 수단은 설치 실측 후 확정 — API 없으면 «확인 불가» 로 두고 화면 캡처 OCR 은 쓰지 않는다: 정관 §0 추측 금지).

**PROCESS** 1. 발행로그에서 게시물 목록 2. 지표 수집(조회 시점 필수 — content-scout 58행 규칙과 같다) 3. `logs/metrics/<날짜>.csv` 누적 4. 이상치만 `reports/<날짜>_metrics.md` + `STATUS:`.

**OUTPUT** CSV(기계 판독) + 리포트. 발행로그 쓰기 금지.

**RULES — 금지 자리** 해석·추천 금지(«저장이 늘었다» 까지, «저장형 콘텐츠를 늘려라» 는 금지) · 조문 제안 금지 · 발행 금지 · 정본 직접 쓰기 금지.

**GATE** 수집 행마다 조회 시점 존재 · 게시물 수 = 발행로그 게시물 수(전수). 역검증: 시점 없는 행 1건 심어 걸리는지.

**성공지표** 수집 성공률 ≥ 95% (게시물 기준, 30일). keep rate 는 «이상치 보고 → JJ 가 봤다» 로 대체(해석이 없으므로 채택 개념이 약하다).

**FAIL CONDITION** 발행로그를 못 읽음 · CSV 못 씀. 채널 «확인 불가» 는 부분 표기.

**6질문 답** ① 발행로그(정본) + 채널(외부) ② CSV·리포트 유일 작성자 ③ v3.52 편수/게시물 층 · 조회 시점 규칙 ④ 메모리 · 카드 본문(지표만 본다) ⑤ 수집 오류 반복 → R6 ⑥ 이상치 기준(±2σ)이 3회 오탐이면 기준 조정은 JJ 결정(R2).

**하네스 판정** 봇 메모리 = **부채**(누적은 CSV 가 맡는다 — 파일이 기억이다). **채점** 반복 2 · 시간 1 · 검증 2 · 실패 비용 2 · 오염 2 = **9/10** (단 전제 미충족으로 보류).
