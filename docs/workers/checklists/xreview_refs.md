# 크로스 모델 검수 — 참조 조문 발췌 (gumsu 입력 동봉분 · 조문 절만, 근거·이력 주석 제외)

> `xreview.py` 가 체크리스트와 함께 이 파일을 헤르메스 입력에 붙인다. **발췌 범위는 조문 «규칙 문장»만** — 근거(사고 경위·실측표·판본 이력)는 넣지 않는다(공개 예정 텍스트 원칙과의 최소 접점). 원문이 바뀌면 여기도 바꾼다 — 판본 표기가 정본 대조 열쇠다. **개정은 JJ 승인 후 PR.**

## R-4.1 어미 (SKILL §4.1 v3.22 · v3.52)
- 카드 = 헤드라인 반말 훅 허용 + 핵심 1줄·본문 해요체. 카드 헤드라인도 해요체(합쇼체 «…입니다» 금지, v3.52).
- 캡션·고정 댓글·DM = 존댓말. 게이트 `[3]` 은 «…니다/…세요/…어요/…에요/…죠» 로 끝나는 문장을 존댓말로 본다 — **합쇼체·해요체 둘 다 통과**, 반말 종결(«…다/…음/…함»)만 걸린다.
- 캡션 첫 줄은 표지 훅 문장과 같다(반말·해요체 훅이 그대로 온다) — 첫 줄은 어미 검사 대상이 아니다.

## R-5.8-1 집필 (SKILL §5.8-1 v3.20 · v3.47 · v3.52)
- 카드 본문은 내용만 전달한다. 출처 언급(«공식 발표 기준이에요», «X 에 올린 말도»)과 제작 과정 자기 언급(«우리가 그린/만든/그렸»)은 본문 금지. 출처는 하단 크레딧·캡션·킷 각주가 담당한다. 가르는 선: **«우리가/저희가 + 실측 행위»**(«돌려봤어요», «네 과제로 돌려봤습니다»)는 두드려봄 채널 약속이라 위반이 아니고, **«우리가/저희가 + 제작 산출물»**(«저희가 낸 카드를 넣은», «우리가 그린 그림», «규약 문서를 통째로 넣은 질의» 처럼 우리 카드·그림·질의·문서를 언급)은 제작 과정 자기 언급이라 위반이다. 조회 시점 표기(«… KST 기준이에요»)는 위반이 아니다.
- 소재의 고유명사(제품·회사·서비스 이름)는 출처 언급이 아니다.
- 부재 서술 금지: «~는 없습니다», «이게 전부입니다», «~만 나옵니다» 류를 카드에 쓰지 않는다. 사실을 말하는 부정문(«오픈소스는 아닙니다»)은 허용.
- 「확인 못 한 것」 세 유형 중 금지는 ③ «다루지도 않은 주제에 «확인하지 않았습니다»» 뿐. 다룬 주제의 미확인 표기(①)와 확인의 지위 표기(②, «8월 21일 기준»)는 유지.
- 본문 상세는 짧은 문장, 한 카드 한 생각.

## R-5 캡션 (SKILL §5 v3.25 · §5.9 v3.52)
- 캡션 구조: 훅(= 표지 문장) → 이야기 → 💬 토망치랩 코멘트 1회 → 🐰🔨 마무리 1줄 → 해시태그 5(#ai 첫 자리). 금지: 구분선 · 출처 나열·URL·도메인(출처는 카드 크레딧, 전달물 링크는 DM 경로) · 제작·검증 과정 서사(«~로 확인했습니다» 류) · 발행 예고.
- 고정 댓글: 🐰🔨 핵심 각주 1건 + 팔로우 결 + 초과 해시태그 ≤5(캡션과 겹침 0). 검증 언급(«확인한/확인했/대조/검증했») 금지. «다음 편 예고» 는 폐지(v3.52).

## R-6 표지·수치 (SKILL §6 v3.22 · §6.5 v3.52 · v3.50)
- 표지 훅에는 소재 고유명사가 최소 1개 있다. 말미 물음표 허용(v3.51).
- 수치는 조회 시점 기준으로 표기한다(«N만 회 (날짜 기준)»).
- 킷의 사실 수치는 편의 FACTS 와 일치해야 한다 — 덜 싣는 건 자유, 적은 건 맞아야 한다. 수치가 같아도 비교의 방향(누가 더 크다·증가/감소·긍정/부정)이 카드·캡션·킷 사이에서 뒤집히면 위반(기계 검사 사각).
