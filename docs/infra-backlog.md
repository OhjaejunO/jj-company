## 원인 — 절전이 아니라 **종료**다

**Fast Startup(하이브리드 종료)이 켜진 채 «종료»하면 `Kernel-Power 42` 가 남는다.**
그것이 절전 진입처럼 보였다. 실제로는 전원이 꺼진 상태이고, **종료 상태에서는 RTC 기상
타이머가 발화하지 않는다.** JJ 가 앞으로도 종료 방침이므로 `WakeToRun` 은 **성립하지 않는다.**

**실측 (2026-08-22 · 최근 7일 · `Kernel-Boot` id=27 의 `BootType`)**

| 기동 유형 | 건수 |
|---|---|
| 하이브리드 부팅 (Fast Startup) | **9** |
| 콜드 부팅 (완전 종료에서) | **3** |
| 최대 절전 복귀 | **0** |
| **절전 복귀** | **0** |
| **합계** | **12회 — 전부 «부팅»** |

**«기상»이 한 번도 없었다.** 모든 저전력 이탈에 `Kernel-Boot 27`(부팅 이벤트)이 붙어 있다 —
진짜 절전 복귀라면 부팅 이벤트 없이 `Power-Troubleshooter 1` 만 남는다. 이것이 판정의 근거다.
`powercfg /lastwake` 도 **「절전 모드 해제 기록 카운트 - 0」**, 기상 원인 `WakeSourceType=0`(Unknown).

## 판정 — 왜 끄는가

**켜 둔 채로 두면 «설정은 됐는데 안 된다»가 남아 다음에 또 원인을 찾게 된다** (JJ).
`WakeToRun=True` 는 **되지 않는 능력을 주장하는 값**이라 거짓 신호다. 끈다.

- 실행: `scripts\waketorun-off.ps1` — 🔴 **관리자 PowerShell 필수.**
  - **비권한으로는 `Set-ScheduledTask` 가 «성공»을 돌려주고 값은 안 바뀐다** (2026-08-22 실측).
    정관 §0 «조용히 실패하는 코드» 그대로라, 스크립트가 **변경 후 값을 다시 읽어** 안 바뀌었으면 `FAIL` 로 끝난다.
  - `Settings` 를 통째로 새로 만들지 않고 **기존 객체에서 `WakeToRun` 한 필드만** 바꾼다 —
    새로 만들면 `StartWhenAvailable`·`S4U`·`MultipleInstances` 가 기본값으로 날아간다(8/21 방식 승계).
  - 검증에 **StartWhenAvailable·S4U 보존 여부**를 같이 넣었다. 끄는 것만 보면 딸린 것이 날아가도 통과한다.

## `UNATTENDSLEEP` — **되돌리지 않는다 (판정)**

`WakeToRun` 때문에 120 → 1800 으로 올린 값이다. 그러나 —

- **끄는 이유가 여기엔 없다.** `WakeToRun=True` 는 **되지 않는 능력을 주장**해서 거짓 신호였지만,
  `UNATTENDSLEEP=1800` 은 **그냥 값**이라 아무것도 주장하지 않는다. 무해하다.
- 되돌리는 것도 **관리자 작업**인데 얻는 것이 0 이다.
- 나중에 절전 방식으로 바꾸면 `WakeToRun` 과 **같이** 다시 올려야 한다 — 붙여서 기록해 둔다.
- ⚠️ **현재값은 확인하지 못했다** — `powercfg /q SCHEME_CURRENT SUB_SLEEP <UNATTENDSLEEP GUID>` 가
  설정 항목을 출력하지 않는다(구성표에 노출되지 않는 상태로 보인다). **「1800 으로 되어 있다」는
  2026-08-21 기록을 승계한 것이지 오늘 실측이 아니다.**

### 1-2. ✅ PowerShell 인코딩 규약 — 검사로 전환 (2026-08-22 신설·해소)

**PS 5.1 은 BOM 없는 UTF-8 `.ps1` 을 시스템 ANSI 로 읽어 비ASCII 를 깨뜨린다.**
그래서 이 레포 스크립트는 **ASCII 전용**이 관례였다 — 각 래퍼 헤더에
「ASCII-only on purpose」라고 적혀 있다.

🔴 **관례로만 지켜지던 것을 새 파일 하나가 깼다.** 2026-08-22 `waketorun-off.ps1` 을
**한글 323자 · BOM 없이** 만들었고 JJ 실행 화면에서 깨졌다. **전수해 보니 기존 11개는 전부 ASCII**
였다 — 규칙이 없어서가 아니라 **검사가 없어서** 났다.

- **조치**: `consistency_audit.py` 에 **`ps1` 감사 신설.** 통과 조건 둘 —
  ⓐ ASCII 전용 ⓑ 비ASCII 를 쓰려면 **UTF-8 BOM**. 역검증 3건(ASCII 통과 / BOM 없는 한글 검출 /
  BOM 있으면 통과)을 같이 넣었다.
- `waketorun-off.ps1` 은 **ASCII 로 다시 썼다** — BOM 을 붙이는 대신 관례를 따랐다.
- ⚠️ **`settings.json` 규칙과 반대 방향이니 헷갈리지 말 것** — 그쪽은 **BOM 이 있으면 파싱이 통째로
  실패**해서 «BOM 금지»이고, `.ps1` 은 **BOM 이 없으면 한글이 깨져** «ASCII 또는 BOM»이다.
  같은 «인코딩» 이야기지만 **요구가 정반대**다.
