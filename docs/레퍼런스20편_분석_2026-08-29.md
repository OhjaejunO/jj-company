## 0. 총평 — 이 묶음의 정체

20편은 2026년 8월 중하순, X에서 동시에 돈 하나의 클러스터다. 파란 배지 계정, 「X기사」 카드, 짧은 데모 영상, 「모르면 늦는다」 훅, 끝에는 팔로우·뉴스레터·컨설팅·제품 깔때기. 20편 중 깔때기가 확인된 것이 14편이다.

그러나 품질은 균일하지 않다. 한 편은 **존재하지 않는 제품 사양을 통째로 지어낸 위조**이고, 반대편 끝의 한 편은 **우리 정관과 같은 측정 규율로 쓰인 글**이다. 이 스펙트럼 자체가 수확이다. 같은 클러스터 안에서 무엇이 글을 믿을 만하게 만드는지가 대조로 드러난다.

우리에게 값이 있는 것은 그록봇 자체가 아니다(도입 판정은 별도 문서·대화에서 이미 「구조 확장 먼저, 그록봇 보류」로 확정). 값은 세 갈래다.

첫째, **에이전트 운영 규율**이 서로 다른 저자에게서 반복 검증된다 — 특히 「자기 보고를 믿지 마라」가 네 곳에서 독립적으로 나온다. 우리 L-009·xreview·게이트가 이미 그 자리에 있고, 조문 근거가 두꺼워졌다.

둘째, **JJ-Brain 연결의 설계도**가 세컨드 브레인 묶음에서 나온다. Raw/Wiki 분리, 볼트 우선 규칙, 라우팅 테이블.

셋째, **소재**. 위조 가이드 발견, 「봇마다 컴퓨터」 오해, 측정 규율 대조 — 편 후보 셋이 재료째로 손에 있다.

## 1. 편별 상세

### ① 자율 에이전트 아키텍처 — 컨텍스트·메모리 엔지니어링

**무엇인가.** 공개 기법 종합. 컨텍스트는 휘발성 RAM, 메모리는 비휘발 SSD라는 프레임. KV캐시 프리픽스 3층(불변 시스템 프리픽스 → 반정적 메모리 슬라이스 → append-only 동적 꼬리), Tree-sitter AST 축약, 4계층 메모리(작업/에피소드/의미/절차), 원자 노트 CRUD, 에빙하우스 감쇠 퇴출, 빠른 안쪽 루프 + 느린 바깥 루프. 끝에 텔레그램 「additional alpha」 깔때기.

**신뢰.** 기법 자체는 업계 통용. 수치(토큰 60% 절감, 캐시 적중 90%)는 출처 없음.

**우리 연결.**
- 「선별된 원자 사실 50개가 방치된 조각 5만 개를 이긴다」 = clause-backlog가 C-1~C-26으로 쌓이기만 하는 상태의 진단. 감쇠·퇴출에 해당하는 것이 우리의 「정리 회차」인데 계속 밀려 있다. **C 작업 우선순위 근거.**
- 프리픽스 고정·꼬리 가변 = xreview 입력(시스템 프롬프트 22,746자 + 도구 스키마가 대부분)과 gumsu 툴셋 14개 문제의 같은 자리. 백로그 12번(툴셋 제거)과 묶어 볼 것.
- 4계층 메모리 대응: 편 로그=에피소드, FACTS=의미, 정관·스킬=절차. 우리에게 없는 것은 **비동기 통합 루프**(세션 후 원자 사실 추출) — 지금은 등재를 세션이 손으로 한다. 당장 채택은 아니고 관찰.

**처분.** 참고 보존. 채택 1건(C 작업 근거 보강).

### ② 그래프·루프 엔지니어링 (Grokbot+Kimi, @0xCodez 계열)

**무엇인가.** 이 묶음에서 가장 공학적으로 정직한 글. 「문서화 안 됨」을 아홉 번 명기하고 제안 패턴과 공식 기능을 끝까지 구분. 외부 루프(Grokbot)/내부 라운드(Kimi), 정지 규칙 6종(DONE/BLOCKED/승인필요/3라운드/핑거프린트 반복/원천 낡음), 멱등키 2종(라운드 키 + `:commit` 효과 키), 효과 선점→실행→영수증→완료 마커→재기동 조정, tmp+rename 원자 쓰기, 단일 작성자 규칙, 해시 체인 append 로그와 그 한계(「같은 OS 사용자의 변조는 못 막는다」), 훅 fail-open 경고, 중첩 하네스 간극(외부 승인이 내부 도구 호출을 못 본다).

**신뢰.** 높음. 우리가 8/28 하루 종일 피 흘리며 배운 것들이 이 글엔 규칙으로 이미 적혀 있었다.

**우리 연결.** 이 글의 절반이 우리 시스템의 거울이다.
- 해시 체인 한계 = 3확인 단서(「만들 수 없다」가 아니라 「이 회차에 만들지 못했다」).
- 훅 fail-open = vault-health 프로브를 양방향으로 설계한 이유.
- 단일 작성자 = claim 파일. 원자 쓰기 = 우리 state 처리.
- **채택→구현 완료:** 시작 이벤트 선기록(`run.started`, PR #111)과 효과 영수증·재기동 조정(선점→확정 2단계, `plan_resume`)은 이 글에서 뽑아 이미 워커에 넣었다. 8/28 무기록 종료 3건과 「재실행=중복 발행」 결함의 해법이었다.
- 핑거프린트 무진전 조기 중단 → xreview 재시도 3회에 적용 후보(같은 무효 출력 반복 시 조기 종료). **미적용, 등재 대기.**
- 지식그래프·DAG 부분은 현재 규모에 과함. 단일 작성자 + inbox 패치 구조는 우리 PR 흐름이 이미 그 모양.

**처분.** 자료함 1급. 채택 2건 구현 완료, 1건(핑거프린트) 등재 대기.

### ③ 헤르메스 에이전트 마스터클래스 (진품)

**무엇인가.** Nous Research의 Hermes Agent 해설. SOUL.md(정체성, 시스템 프롬프트 1번 슬롯), 3계층 메모리(MEMORY.md 2,200자·USER.md 1,375자 → SQLite FTS 세션 검색 → 외부 제공자 8종), 자기 진화 스킬(skill_manage, 5+ 도구 호출 완료·오류 극복·사용자 정정 시 스킬 자동 생성), Curator(30일 미사용 stale, 90일 보관, **자동 삭제 없음**, 정리 전 tar.gz 스냅샷, pin 보호), GEPA(오프라인 진화 최적화 — 에이전트에게 묻지 않고 실행 흔적을 읽어 개선, PR로만 반영), 90턴 하드캡(서브에이전트와 예산 공유), 프로필 격리, 크론.

**신뢰.** GitHub 실물(NousResearch/hermes-agent, hermes-agent-self-evolution)과 대조 — 설치법·파일 구조·GEPA 레포·ICLR 2026 Oral까지 일치. **진품.**

**우리 연결.**
- **「에이전트는 거의 항상 자기가 잘했다고 생각한다」(커뮤니티 확인 약점) → GEPA는 흔적을 읽는다.** 자기 보고 불신 4사례 중 첫째. L-009·gumsu keep rate 판정 보류(자기 평가 아닌 실측 대기)와 같은 뿌리. 조문 근거.
- **Curator 설계 = C 작업(백로그 정리)의 틀.** 정리는 삭제가 아니라 보관, 정리 전 스냅샷 의무, 핵심 항목 pin. 그대로 옮겨 쓸 수 있다.
- 오케스트레이터-실행자 분리(Hermes 조율, Claude Code 실행) = 실장-클로드코드 구조 그대로. 90턴 공유 예산 하드캡은 우리에게 없음 — 폭주 위임 체인 방지용 등재 후보.
- progressive disclosure(스킬 목록은 이름+설명 ~3k 토큰, 본문은 필요 시) = gumsu 툴셋·xreview 입력 문제의 해법 방향.

**처분.** 자료함 1급. 채택 후보 3건(자기 보고 조문 근거·Curator 틀·턴 예산).

### ④ Hermes 마스터클래스 2편 — **위조**

**무엇인가.** 같은 제품명을 걸고 전혀 다른 설치법을 서술. `git clone hermes-agent/hermes` + npm(Node 18+), CLAUDE.md가 「운영 헌법」, MCP를 .env 환경변수로 설정, `MODEL_NAME=claude-opus-4-5`, schedule.json. 끝은 @cyrilXBT 팔로우 깔때기.

**신뢰.** **0.** 실물은 Python 계열 + curl 설치 + SOUL.md. 언급된 레포 주소는 존재하지 않고, MCP를 환경변수로 설정한다는 서술은 MCP 동작 방식 자체와 안 맞는다. 유창하고 내부적으로 일관돼서, 진품(③)과 나란히 놓고 실물과 대조하지 않으면 못 잡는다. 다만 내부의 일반론(품질 게이트, 재시도 패턴, 주간 리뷰)은 범용 조언으로는 무해 — 위험은 제품 사양 부분이다.

**우리 연결.**
- 우리 링크확인·공식 위계 규칙(「X에 공식 링크 있으면 원문 열람 후 FACTS 확정」)이 왜 존재하는지의 실증. 이 글을 소재 조사에서 근거로 썼다면 게이트 27항이 잡았을까? — **잡을 장치가 없다.** 2차 출처의 제품 사양 서술을 실물과 대조하는 검사는 게이트에 없다. 사람 규율(링크확인)에만 얹혀 있다. C-8 계열 등재 후보.
- **소재 1급.** 「같은 제품, 두 개의 설치법 — 하나는 존재하지 않는다」. GitHub 대조 증거까지 확보됨.

**처분.** 위조 표본으로 보존(자료함에 「위조」 라벨 필수). 소재 후보 1순위.

## 2. 관통 패턴 — 20편이 합쳐서 말하는 것

**자기 보고를 믿지 마라 (독립 4회).** ③ GEPA(에이전트는 거의 항상 자기가 잘했다고 생각한다 → 흔적을 읽는다), ⑬(봇의 자기 보고는 당신과 같은 맹점 → 손 대조), ⑮(요약 말고 흔적), ⑰(Scout/Critic 분리). 우리의 L-009, xreview, 게이트, gumsu 보류 판정이 전부 이 자리다. 서로 모르는 저자 넷이 같은 결론에 도달했다는 것이 이 원칙의 가장 강한 근거이고, 조문 개정 시 이 4사례를 근거란에 인용한다.

**되돌림 가능성이 승인선이다 (⑪⑬⑭⑮⑯⑱).** 「1분 안에 못 되돌리면 파킹」, 「외부가 보는 것·돈·삭제는 정지」, 「36건 초안·0건 발송이 올바른 금요일」. 우리 발행 C등급·승인 장치·부분 발행 「보고하고 멈춘다」와 동형. 우리 쪽이 한 걸음 더 가 있다 — 그들은 프롬프트 규율, 우리는 파일시스템 장치.

**규칙에는 검사가 짝으로 붙는다 (⑪⑭).** 30초/60초 검증 가능 체크. 우리 정관의 빈자리(검사 없는 조문)를 정확히 겨눈다.

**측정 장치는 행동보다 먼저, 소급 불가 (⑯②).** 필드 선설치, run.started 선기록. 8/28~29 우리가 두 번 아팠던 자리(무기록 종료, 발행 시각 구술 근사).

**원천과 파생을 가르고, 파생은 부술 수 있게 (⑨⑰⑯).** Raw/Wiki, EVIDENCE/INFERENCE, 별칭 테이블(자산) vs 데모(파생). 우리 정본/산출물·검증로그/지면 분리와 동형.

**프로세스가 자산이고 하네스는 갈아탄다 (⑱③⑫).** 파일로 존재하는 워크플로만 이식된다. 그록봇 보류 판정의 뼈대.

## 4. 소재 후보 3건 (재료 확보 상태)

1. **「같은 제품, 두 개의 설치법 — 하나는 존재하지 않는다」** — ④ 위조 가이드 vs ③ 진품 vs GitHub 실물. 대조 증거 확보 완료. 우리 채널의 축(공식 대 떠도는 말)에 정확히 맞음.
2. **「봇마다 컴퓨터가 생긴다는 오해」** — X 클러스터의 핵심 오해 vs 공식 문서(계정당 1대·보안 경계 아님). ⑫와 공식 문서가 근거.
3. **「6일짜리 숫자를 안 내놓은 사람」** — ⑯을 축으로 한 측정 규율 편. 클러스터의 「10배·100배」 수치들이 대조군.

셋 다 남의 글 비판이 아니라 「공식·실물 대조」 형식으로 만들 수 있어 저격 편이 되지 않는다. 단, ①은 특정 계정의 글을 위조로 지목하는 셈이라 지면에서 계정명을 다룰지(익명화할지)는 JJ 판정 필요.
